# 运行结构

默认入口为`compat-runtime/newpath/__main__.py`，控制器位于`controller.py`。工程工具和测试由开发者显式运行。

|阶段|职责|
|---|---|
|初始化|保留当前原图，建立1920×1080工作图和同源坐标辅助图，冻结运行身份|
|背景|保留连续场景、场景人物和固定空装饰容器，保存请求与真实回图|
|整页前景|保留指定前景素材，用安全纯色生成空区，由程序转换为透明采样参考|
|页面描述|依据原图登记文字与最终位置，依据实际前景另量取素材裁片位置|
|组件板|从生成前景制作参考板，生成真实透明PNG并按槽位裁切|
|组装|写入原生文字、基础对象及独立图片，保存PPTX、回执与结束状态|

## 调用、登记与恢复

调用前保存请求，首次`invoke_once`对应当前任务的一次调用许可。实际调用数和输出数由宿主据实登记，服务未暴露的信息保持未知。

已有多张回图按返回顺序逐张复核，采用首个技术、来源与角色可用的现有结果，保留额外输出与实际数量。缺少观察或登记字段时继续补齐同一文件。等待和登记修正不消耗修复次数。

R28启动命令启用`bounded-existing-return-recovery/2`。每个任务最多自动修复一次，全作业最多两次。背景修复以已保存的失败背景为第一编辑目标，原图提供事实参照。真实失败、来源绑定冲突和用尽的修复额度保留现场及具体原因。

## 图像归属

原图决定文字、源范围和最终摆放。实际生成前景作为组件采样参考。整页前景所需主体完整且可准确采样时，主体外残留的固定容器记入观察。最终组件板逐成员核对完整性、真实字样与透明周边。

照片、截图、扫描件和拼贴图保留完整矩形，图内文字、人物与标志随图保留。去底图、归一化图或其重编码副本不能冒充另一次工具原始回图。

## 输出和验证

默认首次图像任务数为背景、整页前景各一项，加上实际组件板数K。计划任务数与实际调用、服务计费和耗时分别记录。

`done`表示技术交付。文件清单、协议测试、图像质量、真实端到端时间与Office编辑检查各有自己的验证范围。用户明确要求时，`--diagnostics`导出实际作业记录。诊断资料、用户图片与私人日志保存在开发区。
