# 架构与验证边界

默认入口为 `compat-runtime/newpath/__main__.py`，控制器在 `controller.py`。`engineering/` 与 `tools/` 只在开发者主动运行时工作，不是默认生图步骤。

| 阶段 | 主要数据与职责 |
|---|---|
| 初始化 | 保留本次输入，生成 1920×1080 工作图与 25/50/5 辅助尺，记录源图和运行身份 |
| `layers` | 下发背景与真实透明前景任务，保存调用前请求及真实回图，先登记背景 |
| `describe` | 宿主依据原图与辅助尺，一次登记布局、原生文字/几何和艺术素材 |
| `boards` | 按像素需求规划普通透明组件板；可选的独立主标题另设任务；每批最多三项 |
| 提取与组装 | 校验透明通道和参考归属，按安全分格提取，保留真实 RGBA；组装原生对象及图片 |
| `done` | 发布 PPTX 与收据，保持终态；不因此授权额外生成 |

新作业默认使用真实透明前景与组件，不走色键去底。旧 API 和旧作业保留原兼容策略，不能把它们的默认参数或旧说明当成当前 CLI 工作流。标题采用等比放置；普通组件保留各自槽位和几何合同。透明间隙、主体归属或安全边界不明确时保留警告及失败，不删除真实像素来伪造通过。

## 调用与回图

新 CLI 冻结版本身份、`explicit-start/1`、`audit-existing-return/1` 和 `reviewed-existing-output/1`。调用前必须登记完整提示词、参考图及所需参数；唯一许可不等于服务端调用证明。已知回图归属按任务、尝试、文件和像素身份记录；同图跨任务复用或已知工具输出 ID 冲突不能靠改名、重编码绕过。

调用后实际 prompt 可得才登记，不可得保持 unknown。match、mismatch 和 unknown 表示宿主报告与锁定请求的比较；偏离审计不能代替角色核对。真正的错主体、参考图冒充、透明失败和损坏文件不能仅靠一个审计 warning 放行。一次调用的完整多回图只按真实顺序采用第一份可用已有结果，保留其余原件与核对记录。

## 任务数、调用数与时间

无重试时的计划图像任务数为 **`2 + K + W`**：背景和前景各一项，`K` 是实际规划的普通组件板数，`W` 是实际下发独立主标题任务的 0 或 1。每批三项不是总板数上限。

计划任务数不等于实际工具调用次数，更不能推算提供方计费。调用次数和输出数量来自宿主如实登记；未知保持未知。重复文件、轮询、登记修正和本地提取不自动等于新增服务调用。

`controller_wall_seconds` 是控制器初始化至发布的时间，包含等待，未必覆盖用户完整任务；`processing_seconds` 仅覆盖部分本地处理。真实端到端时间、图像工具等待与本地处理应分别记录，不能将单元测试或缓存回放耗时当成图片转 PPT 的交付速度。

## 证据能说明什么

| 检查 | 可支持的结论 | 不能据此宣称 |
|---|---|---|
| ZIP、清单与哈希核对 | 文件范围、内容一致及版本身份 | 版权认证、服务端执行或视觉正确 |
| 单元/集成测试 | 覆盖到的本地状态、保护与结构行为 | 所有截图、字体和平台均可用 |
| 程序合成 CLI 演练 | 新作业流程与本地 PPTX 组装可执行 | 真人角色核对、模型效果或真实调用时效 |
| 私有缓存回放 | 指定已有回图可在固定条件下处理 | 本轮重新生图效果或服务可靠性 |
| PowerPoint 打开与对象检查 | 已检查环境下的显示与对象结构 | 全平台编辑能力或全页视觉验收 |

既有 Windows 检查包含 PowerPoint 只读打开与显示；整体还原和手工编辑不能由此一并认定。缺少匹配字体时保留明确估算，标尺跨字体边缘标签问题仍列为 Beta 限制。Linux 和其他 Office 环境须保存独立验证结果，不继承 Windows 的结论。见 [KNOWN_ISSUES](../KNOWN_ISSUES.md)。
