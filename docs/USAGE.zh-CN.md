# 使用说明

## 使用运行包

使用 `PPT Rebuilder King ChatGPT-20261024-Beta1.zip`。宿主需要已有 Python、Pillow、NumPy、Node.js，以及能够接收参考图并生成真实 alpha PNG 的图像工具。运行包携带 JavaScript 依赖，不提供模型账户、额度、外部服务凭据或字体。

1. 创建独立项目，上传这一版运行 ZIP，设置根 `PROJECT_INSTRUCTIONS.txt` 中的项目指令。不要混用多个版本或旧作业状态。
2. 在新对话附上本次页面图片，要求读取本项目 ZIP，按项目指令与包内工作流还原为可编辑 PPTX。
3. 宿主解压并读取 `compat-runtime/SKILL.md`，从程序目录之外的新作业目录启动。后续继续同一目录。
4. 宿主按控制器任务调用图像工具，保存、实际查看并登记每份回图；到 `done` 后立即提供 PPTX 下载及实际缺项、警告。

运行来源只有当前包内 SKILL 与项目指令。开发文档和公开材料索引不参与默认生成流程。

## 当前流程

当前图片 → 工作图与辅助尺 → 背景和透明前景 → 一次页面登记 → 独立标题与透明组件板 → 原生文字、基础对象和图片组装 → PPTX。

背景保留自然融合的场景主体；独立纸卡、标签、图标和插画属于前景；普通正文与简单几何使用原生对象。照片任务仍需照片，不能把标题图片登记进照片框。真实透明是 PNG alpha，不接受绘制的棋盘格或白色矩形冒充透明。

`generate` 是准备卡。宿主读取对应 `prompt_file` 的完整原文，按 `begin_template` 登记拟提交请求；只有首次 `invoke_once` 许可该任务调用一次。执行时保留指定参考图、尺寸、透明要求和单张请求，不将不同任务都改成同一段提示词。

回图先保存，再按实际像素填写 `role_review`、`output_sha256` 和本次 `request_sha256`。核对背景、前景、标题或组件成员是否匹配，并如实记录光晕、装饰或画质偏差。角色核对是宿主声明，不是程序自动语义识别或完整视觉验收；不从 caption 复制看图结论。

## 等待、意外多回图与真正失败

- `await_results` 只等待或登记已经存在的结果。路径、尺寸或登记字段出错时纠正登记，不因此重画。
- 明确一次实际调用意外返回多张时，保存完整原件，按真实顺序提交 `returned_outputs` 和每图独立核对。程序只采用第一份技术、来源和角色可用的已有结果，不做美观择优，不额外调用，也不为采用已有结果反复索要确认。
- 多次或未知调用、错误主体、假透明、源图替代、任务错绑以及用户停止仍受保护。真正失败保留现场并说明；新的生成重试仍须明确授权，不能伪造 `done`。
- 用户全局停止新增生成后，采用已有某项结果不会自动解除停止。正在调用的结果可以保存；剩余首次调用须按真实后续授权恢复。

## 源码与运行包

源码 ZIP 用于开发；先准备依赖，再运行 `tools/build_release.py` 生成运行 ZIP。源码中的 `compat-runtime` 不等同于已经完成清单构建的发行目录。不要手改哈希或关闭校验来运行改动版本。

最终运行 ZIP 解压后，程序入口为 `compat-runtime` 内的 `python -m newpath`；启动参数及本版身份以其中 SKILL 为准。作业目录必须在程序目录外。旧版本和正在运行的旧作业原样保留，回退只让新作业重新使用旧运行 ZIP，不复制旧 state 到新版本。

## 输出检查

普通文本框和支持的基础图形为原生对象；复杂艺术字、纸卡和插画为可移动图片。图片里的文字、嵌入照片内容和背景场景不等于逐字或逐物体可编辑。表格为对象组合，公式存在支持范围。

文件写出与 `done` 表示技术交付，不保证整体还原、字体显示、提供方调用或十分钟时效。需要视觉或编辑验收时，应另外打开 PPTX 检查；正常生成流程不自动追加预览、诊断包或返修调用。已知边界见 [KNOWN_ISSUES](../KNOWN_ISSUES.md)。
