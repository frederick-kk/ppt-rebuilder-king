# 在 ChatGPT 网页版使用

**下载运行 ZIP → 整包上传 ChatGPT 项目的「来源」→ 保存项目指令 → 发送单页图片和提示词 → 下载 PPTX。**

普通使用者不需要安装本地 Codex，也不需要在电脑上解压运行 ZIP 或安装开发依赖。以下步骤对应 `2026.11.05-package.1`（发行整理版）。仓库现已公开，可直接下载运行 ZIP 和配套项目指令。

## ① 从 GitHub 下载运行 ZIP

直接点击下面两个入口：

- **[下载 ChatGPT 运行 ZIP](https://github.com/frederick-kk/ppt-rebuilder-king/releases/download/v2026.11.05-package.1/PPT-Rebuilder-King-ChatGPT-20261105.zip)**
- **[下载配套项目指令 TXT](https://github.com/frederick-kk/ppt-rebuilder-king/releases/download/v2026.11.05-package.1/PPT-Rebuilder-King-20261105-PROJECT-INSTRUCTIONS.txt)**

项目指令也可[在线查看并复制全文](CHATGPT_PROJECT_INSTRUCTIONS.txt)。将全文保存到项目设置即可，执行流程保持不变。

运行 ZIP 下载后的文件名是 `PPT-Rebuilder-King-ChatGPT-20261105.zip`。记住保存位置，**不要解压、不要改名，下一步直接把这一份 ZIP 上传到 ChatGPT。** 本次仅精简发行内容，程序和生成规则保持不变。

也可以打开 [本版 Releases 下载页](https://github.com/frederick-kk/ppt-rebuilder-king/releases/tag/v2026.11.05-package.1)，向下找到 **Assets（附件）** 并展开，下载上面对应的运行 ZIP 和项目指令 TXT。

这里需要的是已经打包完成的 **ChatGPT 运行 ZIP**。`Source code`、名字带 `source` 的源码 ZIP 和绿色 **Code → Download ZIP** 用于源码开发，普通使用无需下载，也不需要先解压其他外层交付包。

## ② 在 ChatGPT 网页版新建项目

打开 ChatGPT 网页版，点击「项目」→「新建项目」，在创建时将记忆设置选择为「仅限本项目」，以账号实际界面提供的选项为准。

建好后，确认自己就在这个项目里。后面的 ZIP、项目指令和对话，都放在同一个项目下。一个项目先使用这一版运行包，避免混入旧版 ZIP 或旧作业文件。

## ③ 上传 ZIP，设置项目指令

1. 在项目「来源」上传刚下载的 `PPT-Rebuilder-King-ChatGPT-20261105.zip`，保持压缩状态。
2. 打开配套的 `PPT-Rebuilder-King-20261105-PROJECT-INSTRUCTIONS.txt`，复制全文。
3. 打开项目右上角的「项目设置」，将全文粘贴到「项目指令」并保存。

确认来源里能看见 ZIP，项目指令也已经保存，再往下发图片。不要只上传 ZIP 而漏掉项目指令。

- **思考程度：中等到极高；** 有 Pro 的也可以尝试 Pro，以自己账号实际提供的选项为准。
- 作者目前按已跑通的 5.6 配置演示；个人测试结果不代表所有模型、账号和图片的结果。

所用对话需要具备读取项目文件、执行代码和参考图生图的能力。运行 ZIP 本身不提供模型账户、额度或外部服务凭据。

## ⑤ 单页高清图片和提示词一起发送

在这个项目内新开对话，上传**一张单页高清图**，同时发送下面这句：

> 请读取本项目指定的运行 ZIP，按项目指令和包内工作流，将这张截图还原成可编辑 PPTX。

每次先处理一页。如果手里是六格缩略图，应先准备各页高清原图，再分别还原。

等待它提供 PPTX 文件，下载到电脑，用 WPS 或 PowerPoint 打开，检查文字编辑、图片移动和页面显示。普通文字与支持的基础图形为原生对象；复杂艺术字、纸卡和插画为独立图片，可移动、缩放，不等于其中每个字都可逐字编辑。

正常流程会由 ChatGPT 读取并解压项目中的运行 ZIP，按包内控制器连续执行。你无需手动操作内部命令；完成后直接获取 PPTX 和实际缺项、警告。正常生成不会自动追加预览、诊断包或返修调用。若遇到真正失败，保留当前对话和现场，再根据明确说明处理，不以反复点击或重复发送图片来自动重画。

## 输出与已知边界

图片里的文字、嵌入照片内容和背景场景不等于逐字或逐物体可编辑。表格为对象组合，公式存在支持范围。

文件写出与 `done` 表示技术交付，不保证整体还原、字体显示、提供方调用或十分钟时效。需要视觉或编辑验收时，应另外打开 PPTX 检查。已知边界见 [KNOWN_ISSUES](../KNOWN_ISSUES.md)。

<summary>开发者与排障说明：内部工作流、回图登记和源码入口</summary>

运行环境需要已有 Python、Pillow、NumPy、Node.js，以及能够接收参考图并生成真实 alpha PNG 的图像工具。运行包携带 JavaScript 依赖，不提供字体。

宿主解压并读取 `compat-runtime/SKILL.md`，从程序目录之外的新作业目录启动，后续继续同一目录。运行来源只有当前包内 SKILL 与项目指令，开发文档和公开材料索引不参与默认生成流程。

### 当前流程

当前图片 → 工作图与辅助尺 → 背景和透明前景 → 一次页面登记 → 独立标题与透明组件板 → 原生文字、基础对象和图片组装 → PPTX。

背景保留自然融合的场景主体；独立纸卡、标签、图标和插画属于前景；普通正文与简单几何使用原生对象。照片任务仍需照片，不能把标题图片登记进照片框。真实透明是 PNG alpha，不接受绘制的棋盘格或白色矩形冒充透明。

`generate` 是准备卡。宿主读取对应 `prompt_file` 的完整原文，按 `begin_template` 登记拟提交请求；只有首次 `invoke_once` 许可该任务调用一次。执行时保留指定参考图、尺寸、透明要求和单张请求，不将不同任务都改成同一段提示词。

回图先保存，再按实际像素填写 `role_review`、`output_sha256` 和本次 `request_sha256`。核对背景、前景、标题或组件成员是否匹配，并如实记录光晕、装饰或画质偏差。角色核对是宿主声明，不是程序自动语义识别或完整视觉验收；不从 caption 复制看图结论。

### 等待、意外多回图与真正失败

- `await_results` 只等待或登记已经存在的结果。路径、尺寸或登记字段出错时纠正登记，不因此重画。
- 明确一次实际调用意外返回多张时，保存完整原件，按真实顺序提交 `returned_outputs` 和每图独立核对。程序只采用第一份技术、来源和角色可用的已有结果，不做美观择优，不额外调用，也不为采用已有结果反复索要确认。
- 多次或未知调用、错误主体、假透明、源图替代、任务错绑以及用户停止仍受保护。真正失败保留现场并说明；新的生成重试仍须明确授权，不能伪造 `done`。
- 用户全局停止新增生成后，采用已有某项结果不会自动解除停止。正在调用的结果可以保存；剩余首次调用须按真实后续授权恢复。

### 源码与运行包

源码 ZIP 用于开发；运行 ZIP 仅保留运行所需文件与必要许可，不携带开发工具、测试或历史资料。构建与校验说明见 [中文开发说明](../README.zh-CN.md#构建与校验开发者使用)。

运行包根目录为 `PPT Rebuilder King`。内部程序身份仍为 `PPT Rebuilder King-20261025-quality-test`，供 `--expected-package` 和首次 CLI 回传核对。外层归档已重新打包，核对下载页的本版 SHA256 和两层文件清单；程序文件逐项保持不变不代表整个 ZIP 字节相同。

最终运行 ZIP 解压后，程序入口为 `compat-runtime` 内的 `python -m newpath`；启动参数及本版身份以其中 SKILL 为准。作业目录必须在程序目录外。GitHub 仅提供当前版本。正在运行的作业不强制迁移，不复制旧 state 到新版本；维护者如需本地回退，仅让新作业使用已保留的本地旧包。
